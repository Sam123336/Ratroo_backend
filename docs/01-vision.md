# Product Vision

## Mission

Yatroo helps people move through Indian cities and districts with confidence by combining official transit data, provider integrations, community verification, and intelligent journey planning.

The platform starts with buses because buses are the highest-coverage public transport mode in India. The system is designed to grow into metro, rail, ferry, walking, shared mobility, disruptions, fares, places, and trip assistance.

## Product Principles

- India-first coverage: state, district, city, town, and peri-urban mobility matter.
- Data humility: official APIs are preferred, but real coverage often requires HTML ingestion, PDFs, route boards, depot data, and community validation.
- Provider isolation: one broken provider must not break another.
- Canonical model: every source maps into one internal transit model.
- Explainable journeys: users should know why a route was recommended.
- Freshness over perfection: stale verified data is worse than incomplete but honest data.
- Community as an operating system: local riders, conductors, depots, and volunteers improve gaps that official data cannot cover.

## Primary Users

| User | Need |
| --- | --- |
| Daily commuter | Fast routes, arrival confidence, fewer transfers |
| Occasional traveler | Simple search, landmarks, route confidence |
| Rural or district traveler | Bus availability even when data is incomplete |
| Student | Affordable, repeatable route discovery |
| Tourist | Multi-modal navigation and place-aware suggestions |
| Admin operator | Provider health, import status, source quality |
| Community verifier | Easy route/stoppage correction and reputation |

## North Star

The north-star outcome is: a user can enter any meaningful origin and destination in a covered region and receive a practical route with confidence labels, even if the underlying data source is imperfect.

## Success Metrics

- Search-to-plan success rate
- Journey plan completion rate
- Data freshness by provider and district
- Verified stop and route coverage
- User correction acceptance rate
- Provider import success rate
- Median API latency for nearby stops and journey plans
- Monthly active covered districts
